# DebugLauncher 配置管理与一键启动方案

日期：2026-09-30  
状态：方案文档，描述目标交互和行为，尚未完成实现。

将“编辑配置”和“启动 App”分成两个独立操作：在配置管理窗口中填写完整参数、命名并保存；在主界面选择已经保存的 Host、Client 配置，然后分别启动或一键启动双端。

## 1. 设计目标

当前共享参数输入框需要在 Host 和 Client 之间反复切换，不方便保留两端不同的参数，也不便于切换本机联调、远程连接等使用场景。

新界面应满足：

- 每份配置可以独立编辑、命名、保存和复用。
- Host 和 Client 各自选择配置，彼此独立。
- 常用网络参数使用有名称的输入项，无需手写命令行参数名。
- 主界面直接提供“启动 Host”“启动 Client”“一键启动 Host + Client”。
- 记住上次选择的配置，重新打开后可以直接启动。
- 运行实例显示配置来源和实际参数，便于辨认、关闭和重启。

## 2. 配置粒度

**每份配置对应一个 App 的完整启动设置。** 一键启动使用主界面当前选中的两份配置，不额外要求用户创建一份组合配置。

例如：

| 配置名称 | 类型 | 用途 |
| --- | --- | --- |
| 本机 Host | Host | 在本机启动主机 |
| 本机 Client | Client | 连接本机主机 |
| 测试机 Client | Client | 连接指定测试机 |
| Debug Host | Host | 使用另一份 EXE 或不同调试参数 |

需要区分三个对象：

| 对象 | 保存的内容 | 生效方式 |
| --- | --- | --- |
| 启动配置 | 名称、类型、程序路径、网络参数、额外参数及调试选项 | 编辑后显式保存，供后续启动使用 |
| 主界面选择 | 当前选中的 Host 配置、Client 配置和双端启动间隔 | 记住上次选择 |
| 运行实例 | 启动时的配置快照、实际 UIN、PID、调试端口和运行状态 | 启动后独立存在，不随配置编辑变化 |

## 3. 主界面

主界面只保留配置选择、关键参数摘要、启动按钮、实例列表和日志。完整参数表单放到配置管理窗口。

```text
Host / Client 启动器                                  [配置管理]

Host 配置    [ 本机 Host                 ▼ ]  [编辑]  [启动 Host]
             AICore_profile.exe · 端口 7000 · 房间 1

Client 配置  [ 本机 Client               ▼ ]  [编辑]  [启动 Client]
             127.0.0.1:7000 · 房间 1 · 起始 UIN 10001

[ 一键启动 Host + Client ]                            [关闭全部]
Host 启动后 [ 2 ] 秒启动 Client

运行实例
配置名称        角色       PID       房间     UIN       状态
本机 Host       Host       ...       1        1         运行中
本机 Client     Client     ...       1        10001     运行中

[关闭选中实例]  [重启选中实例]  [查看启动命令]

运行日志 …
```

交互规则：

- Host 下拉框只显示 Host 配置，Client 下拉框只显示 Client 配置。
- 下拉框显示配置名称，下方摘要随选择更新。
- “编辑”直接打开当前选中配置；“配置管理”打开完整配置列表。
- 启动使用已保存的配置，不读取配置窗口里尚未保存的内容。
- 单独启动一端时，只校验该端；另一端没有选中配置时，仍可单独启动。
- 未选择某端配置时，禁用该端启动按钮；双端都已选择时才能一键启动。
- 实例列表空间不足时可以滚动，避免右侧状态被裁切。

## 4. 独立配置管理窗口

左侧显示已保存的配置，右侧编辑当前配置的完整设置。

```text
配置管理

已保存的配置                配置名称：[ 本机 Client             ]
                            配置类型：[ Client                 ▼]
本机 Host
本机 Client                 程序路径：[ …AICore_profile.exe ] [浏览]
测试机 Client
                            主机地址：[ 127.0.0.1               ]
                            端口：    [ 7000 ]   房间：[ 1      ]
                            起始 UIN：[ 10001                   ]
                            [✓] 多开时自动分配不同 UIN

                            额外参数：[                         ]
                            [✓] 显示控制台
                            [ ] 等待 Lua 调试器

                            完整命令预览：……              [复制]

[新建] [复制] [删除]                       [保存] [另存为] [取消]
```

Host 类型只显示 Host 所需的网络字段。Client 类型显示地址、端口、房间和 UIN。额外参数允许输入其他 App 参数，含空格的值使用双引号。

## 5. 每份配置的内容

| 配置项 | Host | Client | 说明 |
| --- | --- | --- | --- |
| 配置名称 | 支持 | 支持 | 必填，保存时避免重名造成选择歧义 |
| 配置类型 | Host | Client | 决定表单字段及主界面下拉框归属 |
| 程序路径 | 独立设置 | 独立设置 | 默认使用 `C:\MiniGame\Bin64\AICore_profile.exe` |
| 主机地址 | 不需要 | 支持 | 默认 `127.0.0.1` |
| 网络端口 | 支持 | 支持 | 默认 `7000` |
| 房间号 | 支持 | 支持 | 默认 `1` |
| 起始 UIN | 不需要 | 支持 | 默认 `10001`，不能使用主机本地玩家 ID `1` |
| 自动分配 UIN | 不需要 | 支持 | 多开 Client 时从起始值分配可用编号 |
| 额外参数 | 独立设置 | 独立设置 | 保留自定义参数输入能力 |
| 显示控制台 | 独立设置 | 独立设置 | 按配置保存 |
| 等待 Lua 调试器 | 独立设置 | 独立设置 | 新建配置默认关闭；迁移时保留旧设置 |
| 完整命令预览 | 只读 | 只读 | 随编辑更新，可复制；实例调试端口在启动时分配 |

网络字段生成与 `StartAICoreHost.bat`、`StartAICoreClient.bat` 一致的 `-MGFNet*` 参数。额外参数中重复填写这些网络参数时，应提示用户修改对应表单字段。

## 6. 编辑与保存规则

| 操作 | 行为 |
| --- | --- |
| 新建 | 创建一份未保存的配置，可选择 Host 或 Client 类型 |
| 保存 | 校验字段后更新当前配置，并刷新主界面的名称和摘要 |
| 另存为 | 使用新名称创建一份独立配置 |
| 复制 | 复制已有配置的全部内容，修改名称和少量参数后保存 |
| 取消 | 放弃本次未保存的编辑，保留原配置 |
| 切换配置或关闭编辑窗口 | 若存在未保存修改，提示保存、放弃或继续编辑 |
| 删除 | 删除选中的已保存配置；主界面的对应选择清空，已启动的实例继续保留 |

配置编辑采用独立草稿。保存成功后，主界面才能使用更新后的内容。编辑、取消和切换配置都不应意外覆盖另一份配置。

## 7. 启动与实例管理

### 7.1 单独启动

“启动 Host”和“启动 Client”直接使用各自下拉框选中的配置。

已有相同配置的 Host 在本启动器中运行时，可以复用并选中该实例；如果同一端口已被参数不同的受管 Host 使用，应指出冲突实例，便于用户关闭旧实例或选择其他配置。

### 7.2 一键启动双端

1. 读取并校验当前选中的两份已保存配置。
2. 对本机联调检查 Client 地址、端口、房间是否与所选 Host 匹配；不匹配时指出具体字段，供用户编辑处理。
3. 启动 Host，或复用本启动器管理的相同配置 Host。
4. 新启动 Host 时，按配置的间隔等待，再启动 Client。建议默认间隔为 2 秒，可调整；这是启动间隔，不代表已验证 Host 网络就绪。
5. 在实例列表显示双端实际运行信息。

Host 启动失败时，不继续启动 Client。Client 启动失败时，已启动的 Host 继续由启动器管理，并明确显示失败原因，用户可以单独重试 Client 或关闭 Host。

### 7.3 自动分配 Client UIN

自动分配的 UIN 属于本次运行实例，保存的起始 UIN 保持稳定。

例如，配置中的起始 UIN 为 `10001`，连续启动三个 Client，实际使用 `10001`、`10002`、`10003`。实例列表及“查看启动命令”显示实际值。

分配时检查本启动器管理的、连接同一地址、端口和房间的 Client。关闭自动分配后，使用配置中的指定 UIN；存在冲突时给出错误提示。

### 7.4 已运行实例

- 实例保留启动时的配置名称、参数快照和实际 UIN。
- 编辑或删除已保存配置，不改变正在运行的实例。
- “重启选中实例”使用该实例的启动快照，保留实际 UIN 和调试端口。
- 要使用修改后的配置，关闭旧实例后，通过对应启动按钮创建新实例。
- “关闭全部”只关闭当前启动器管理的实例。

## 8. 配置存储与迁移

本地配置文件需要保存具名配置集合、主界面选中的两份配置、双端启动间隔和窗口位置。

配置使用稳定标识关联，修改名称后仍保持主界面选择。运行实例保存独立快照，避免依赖一个可能被编辑或删除的配置。

首次升级时，将旧的单份设置迁移为“默认 Host”和“默认 Client”：

- 保留已有程序路径、有效网络参数、控制台和调试选项。
- 旧设置中的角色专属额外参数迁移到对应角色。
- 缺失的另一端使用与脚本一致的默认值，便于本机联调。
- 继续移除已废弃的玩法参数，不恢复 `Games.AppConfigs` 依赖。
- 保存后的配置集合继续留在本地，不进入版本控制。

## 9. 状态与日志

主界面优先显示 App 是否运行、PID、网络端点、房间和实际 UIN。Lua 调试连接状态作为独立信息，避免把“调试未连接”误认为“App 启动失败”。

缺失调试组件时显示一次明确提示，并保留相关路径供排查。普通启动仍可使用；勾选等待调试器的配置应说明其等待条件，避免用户误以为程序卡住。

## 10. 验收标准

- 能独立创建、编辑、保存、复制和删除多份 Host、Client 配置。
- 修改一份配置不会覆盖另一份配置，取消编辑不会改变已保存内容。
- 主界面能够分别选择 Host、Client 配置，并在重开后恢复上次选择。
- 不打开配置窗口即可单独启动 Host、单独启动 Client 或一键启动双端。
- 启动命令使用选中的已保存配置，预览与实际传递参数一致。
- 连续启动 Client 时实际 UIN 不冲突，保存的起始 UIN 不被递增覆盖。
- 相同配置的受管 Host 可以复用，冲突配置有明确提示。
- 双端启动失败时，实例归属、保留状态和错误原因清楚可见。
- 编辑配置不影响现有实例，重启使用实例启动快照。
- 旧配置可以迁移，窗口和控制台等有效设置得到保留。
- 缺失调试组件不会反复刷屏，也不会掩盖正常的 App 运行状态。
