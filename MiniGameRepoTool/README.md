# MiniGame 仓库管理器

可运行的 Windows Python 桌面工具，使用 PySide6 和系统 Git 管理 MiniGame 的多个仓库。支持多套目录与分支方案、可编辑仓库列表、克隆（可复用本机已有工程的 Git/LFS 数据加速初始化）、分支切换、快进更新、失败重试，以及构建设置、生成 SLN 和 IncrediBuild 编译。

工程和文档均位于 **D:\git\Tools\MiniGameRepoTool**。工具位置与被管理的工程位置相互独立；内置方案管理 E:\MiniGame，也可以新建其他根目录的方案。

## 启动

双击 **[Start.bat](Start.bat)**。本机已配置项目专用虚拟环境和依赖，可以直接启动。

在其他机器上，先安装 Python 3.11+ 与 Git for Windows，再运行 Start.bat。首次启动会调用 [Install.bat](Install.bat) 创建本目录下的 .venv 并安装依赖。依赖安装需要网络；以后启动不需要重新安装。SSH 密钥和 Git 凭据沿用机器已有配置。

也可以从终端启动：

~~~powershell
cd D:\git\Tools\MiniGameRepoTool
.\.venv\Scripts\python.exe run.py
~~~

## 日常操作

1. 在“管理方案”中设置根目录、游戏与引擎分支、仓库列表；可以复制方案以维护不同工作目录。已有工程可点“从目录识别”（或用“选择目录”选中含仓库的目录），自动扫描根目录下三层内的 Git 仓库，按 origin 对应内置仓库、按多数仓库的当前分支填分支组，额外仓库固定为当前分支，目录中没有的内置仓库保留但不启用；确认后才替换仓库列表。
2. 勾选仓库，点击“检查状态”，查看各仓库状态和“执行计划”。
3. 点击“同步所选”。只处理所选仓库，各项独立检查和同步；未克隆或空目录会克隆，已有仓库获取目标分支后切换、快进更新。新建工作目录前可点击“初始化计划”，查看每个未克隆仓库能从哪些本地工程复用 Git/LFS 数据（只读，不访问远端）。
4. 从右侧详情或运行日志定位失败原因。处理完成后点击“重试失败”，或“同步此仓库”。
5. 点击右下角“编译构建”，选择“构建设置 / 生成 SLN 工程 / IncrediBuild 编译”，配置参数后执行；可单选一步或按顺序执行多步。

初次打开只读取本地仓库状态。启动扫描和“检查状态”最多同时检查 8 个仓库，完成一个就刷新一个，并显示已完成数和处理中数量。点击检查状态会访问远端并更新目标分支的远端跟踪引用；点击同步才会切换分支和更新工作区。

在仓库行上右键，可以打开该目录的 Windows 原生菜单，使用本机安装的 Git 等 Shell 扩展。菜单针对右键所在行，不改变批量操作的勾选范围。选择菜单项后会重新读取本地状态；如果菜单启动了外部窗口，待外部操作完成后可再次点击“检查状态”。

“管理方案”中的仓库名称右侧新增两个独立选项，按仓库保存，默认关闭：

- **忽略修改提醒**：主列表用灰色“修改提醒已忽略”代替本地修改警告，详情不自动展开修改文件；仍可打开文件列表和 Diff，不改变真实 Git 状态。
- **强制更新（不备份）**：同步时丢弃该仓库的暂存、未暂存和普通未跟踪文件，再切换或快进更新。保留本地提交，分支分叉时停止；被忽略文件和子仓库不清理。仅保存配置或检查状态不丢弃文件。

同步不会自动加入或勾选父仓库；父仓库失败或有本地修改也不阻止选中的子仓库。强制更新需要明确选择该仓库，失败重试仍遵守这一限制。该选项与手动“备份并丢弃所选（Discard）”是两个流程，后者仍会备份。详见[按仓库忽略提醒与强制更新](docs/usage.md#按仓库忽略提醒与强制更新)。

遇到“有本地修改”时，选中仓库，点击右侧“文件改动 / Discard”（也可双击仓库）。列表展示文件路径、已暂存和未暂存状态；双击文件查看 Diff。勾选需要放弃的文件，点击“备份并丢弃所选（Discard）”，核对路径并确认。子模块可以在此查看自己的文件，也可以从父仓库的文件列表中选中子模块后点击“进入子仓库”。

Discard 将选中的已跟踪文件恢复到当前提交，同时丢弃其暂存和未暂存改动；选中的未跟踪文件备份后删除。操作前完整备份工作区文件和暂存改动，完成后可以“打开上次备份”。未勾选文件保留。具体边界和恢复步骤见[文件改动与 Discard](docs/usage.md#文件改动与-discard)。

## 已实现

- 多方案的新建、复制、编辑、删除、导入与导出；JSON 原子保存和上一版备份。
- 内置原批处理的 8 个仓库；支持分支组、每仓库固定分支和列表排序参考。
- 识别缺失、空目录、占用目录、正常工作树、gitfile/worktree、不完整仓库和子模块。
- 按配置列表顺序逐个同步所选仓库；各项独立执行，父仓库失败不阻止子仓库，不自动加入前置仓库。
- 初始化加速（第一版）：按方案配置本地工程来源，逐仓库按远端身份选择来源；Git reference + dissociate 克隆后解除借用，LFS 对象按目标提交复制并校验哈希，缺失部分从原始服务下载；临时目录中完成验证后再就位，失败按配置回退网络克隆或停止。提供初始化计划与本地工程扫描；旧方案保持纯网络下载。详见[初始化加速](docs/usage.md#初始化加速)。
- 区分未提交修改、本地领先、可快进、分叉、远端不匹配、目标分支缺失和认证失败。
- 最多 8 路并行读取仓库状态，逐项刷新与计数进度；共享 Git 目录的 worktree 远端检查互斥。
- 仓库行的 Windows 原生右键菜单，支持本机已安装的 Shell 扩展。
- 按仓库保存忽略修改提醒和不备份的强制更新选项；旧配置默认关闭。
- 文件改动列表、已暂存/未暂存 Diff、未跟踪文件预览、勾选后备份并 Discard，以及进入已配置子仓库。
- 异步执行、实时日志、按仓库过滤、复制与导出、持久化运行结果。
- 停止后续队列，以及中断当前运行的全部 Git/SSH 进程树。
- 统一编译构建窗口，按方案保存 Python、VS/平台、目标、配置、Build/Rebuild/Clean、生成环境变量、IB 目录、日志和超时参数。
- 构建设置、生成 SLN 和 IB 编译可独立执行或顺序执行；步骤失败停止后续，支持配置检查、实时日志、停止与会话中断。
- 同步后自动准备仍仅执行构建设置，并检查全部必需仓库；生成和编译由构建窗口明确选择。

同步保留本地提交，使用 Git 的快进模式和忽略文件防覆盖选项。默认阻止脏工作区；明确启用强制更新后，按上述范围丢弃未提交文件且不备份。分叉、目录冲突等情况仍留给用户处理。工具不自动 stash、reset、clean、rebase，内置操作不提供 commit 或 push 按钮。原生右键菜单的外部扩展按各自功能执行，不经过工具的 Discard 备份流程。

## 配置和日志

默认位置：

~~~text
%LOCALAPPDATA%\MiniGameRepoTool\
  profiles.json       多套方案
  profiles.json.bak   上一版有效保存的备份
  run.lock            同一配置目录的实例运行锁
  runs\               每次同步、环境准备、构建的 JSON 结果与完整日志
  builds\             每次编译构建的完整日志、IB 原始日志和独立会话文件
  discard-backups\    每次 Discard 的文件备份、暂存补丁、清单与恢复说明
~~~

启动参数支持 --data-dir 指定独立配置目录、--no-scan 跳过启动扫描。独立配置目录主要用于测试；并行实例管理同一工程时应使用相同配置目录，共享运行锁。

## 开发和测试

~~~powershell
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe run.py --smoke-test --data-dir artifacts\smoke-data --screenshot artifacts\main-window.png
~~~

测试使用系统临时目录中的真实本地 Git 仓库和离屏 Qt 窗口，覆盖克隆、快进、分支切换、所选仓库独立同步、目录保护、子模块、配置、并行检查与多进程中断、文件 Discard、备份恢复和界面联动。Windows 专用测试在临时中文目录上查询真实 Shell 菜单项，不执行菜单命令。真实 E:\MiniGame 仅用于只读核对文件列表，不执行克隆、更新、环境准备或 Discard。

当前交付为 Python 源码和项目虚拟环境，没有打包独立 exe。验证环境：Windows、Python 3.13.14、Git 2.45.1、PySide6 Essentials 6.11.2。
